# Project Plan

## Project
Real-time anomaly detection across a large universe of financial assets, using an ensemble of Isolation Forest, an LSTM autoencoder, and a small Transformer, plus a streaming simulation that measures detection latency and false-alarm rate.

### Ticker universes
- The config picks which universe file to use and an optional `max_tickers` cap, so we can run 100 → 500 → thousands without code changes.
- `us_all.csv` will be generated by `scripts/build_universe.py` from the free NASDAQ Trader symbol directory (NASDAQ + NYSE/other listings), filtering out ETFs, test issues, warrants, and preferreds.
- At scale, record how many tickers were requested, downloaded successfully, survived cleaning, and were scored, plus wall-clock time. Save those counts to `results/` so the "number of assets" in the README is a measured number.
- Known limitation: both lists are current snapshots, so historical backtests have survivorship bias.

## Phases
After each phase: run it, show the output, explain it in plain English, write tests, commit with a clear message, and give the interview explanation.

### Phase 1: Data pipeline
- Download daily and intraday price/volume data for a configurable ticker list (start with S&P 500 tickers).
- Clean it: handle missing values, market holidays, splits, and tickers with bad data.
- Features: log returns, rolling volatility, volume z-scores, price gaps, and rolling correlation to the market (SPY).
- Use time-based train/validation/test splits only. No random shuffling, to avoid lookahead leakage.

### Phase 2: Evaluation setup (build this BEFORE the models)
- Create labeled anomalies two ways:
  - (a) inject synthetic anomalies (price spikes, volume bursts, level shifts) at known timestamps
  - (b) tag real known events (e.g., earnings-day shocks, large single-day moves)
- Metrics: precision, recall, F1, PR-AUC, false alarms per day/month, and detection delay.
- Write a small evaluation module that every model uses the same way.

### Phase 3: Baseline: Isolation Forest
- Train, tune the threshold on the validation set, and report results on the test set.

### Phase 4: Deep models
- LSTM autoencoder (reconstruction error as the anomaly score).
- Small Transformer encoder (also reconstruction or forecast error).
- Keep the models small enough to train on CPU in reasonable time. Show training curves.

### Phase 5: Ensemble
- Normalize each model's scores and combine them (start with a weighted average, tuned on validation).
- Compare ensemble vs. each individual model in a results table.

### Phase 6: Streaming simulation
- Replay test data tick by tick as if it were live, scoring each new data point.
- Measure per-tick latency (p50, p95, p99) and the false-alarm rate over the replay period.
- Save all results to a `results/` folder (CSV + charts).

### Phase 7: Polish
- README with: the rebuild note, architecture diagram (Mermaid), setup instructions, how to run each step, a results table with our real numbers, charts, limitations, and future work.
- Clean code with docstrings and type hints. All tests passing.
- A simple command to run the whole pipeline end to end (Makefile or a single script).

## Decisions log
- Python 3.12.7 instead of 3.11 (3.11 wasn't installed).
- `PYTHONPATH=src` (Makefile, pytest config) instead of relying on the editable install: macOS hides `.pth` files in this iCloud-synced folder.
- Evaluation and models use **daily** data (11 years, real earnings events). 5-minute data is used for the streaming latency test in Phase 6.
- Synthetic anomalies are injected into val/test prices only (train is untouched), then features are recomputed.
- Thresholds are tuned for best F1 on val/synthetic. Models are compared mainly on PR-AUC, and event recall is always read alongside false alarms per day.
- False alarms are reported three ways: per day across all tickers, per ticker-day, and per ticker per month (the last one is comparable across universe sizes).
- Model inputs are standardized per ticker using train-split statistics only. Tickers with fewer than 250 train rows use global statistics.
- Deep models early-stop on the last 10% of TRAIN dates, never on val (val has injected anomalies).
- The LSTM's first run hit the 30-epoch cap while its holdout loss was still falling (test PR-AUC 0.207 / 0.196). The cap was raised to 100 based on the training curve alone; the rerun is the reported result.
- LSTM bottleneck fix: the user asked for a tighter bottleneck chosen by val PR-AUC. The first search wrongly included the original size (32) as a candidate, and it won on val synthetic (0.286 vs 0.277). The rerun restricts candidates to 4/8/16 as instructed and keeps 32's numbers in the search table. Test numbers exist only for 32 and 4.
- Isolation Forest settings were chosen by val PR-AUC. After seeing its test results we deliberately did NOT add new feature sets, because that would tune on test.

## Notes for the README's Limitations section
- Survivorship bias: ticker lists are current snapshots, so stocks that left the index or delisted since 2015 are missing.
- Intraday data is a ~60-day snapshot that depends on the download date (fetch dates are saved in `data/raw/intraday/_manifest.csv`).
- `large_move` real events are defined by |return| / volatility, the same quantity some features measure, so detecting them is partly circular. `earnings_shock` is the fairer real-world test.
- Isolation Forest scores saturate beyond the training range (a 100-sigma move scores the same as a ~3-sigma one), so it misses most one-feature anomalies such as volume bursts.
- Autoencoders can copy anomalies through a loose bottleneck. The original LSTM (bottleneck 32) rebuilt ~78% of big moves; the fixed version (bottleneck 4) rebuilds ~14% but catches fewer volume bursts.
- Event recall can be inflated by alarming constantly (the random baseline gets ~0.89 event recall at ~34 false alarms per day), so it's only meaningful next to the false-alarm rate.
